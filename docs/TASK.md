# Task Tracking

Use this document to record concrete work items for the portfolio. Keep tasks scoped, testable, and linked to the files or behavior they affect.

## Task format

For each task, record:

- **Status:** Not started, In progress, Blocked, or Done.
- **Goal:** The user-visible or engineering outcome.
- **Scope:** Relevant screens, data, or files.
- **Acceptance criteria:** Observable checks that establish completion.
- **Verification:** Relevant commands or manual checks.

## Completion checklist

- [ ] Requirements and affected surfaces are understood.
- [ ] Content remains in the appropriate data/config files.
- [ ] Responsive behavior, accessibility, and light/dark styling are checked where applicable.
- [ ] Relevant tests, lint, and build checks are run.
- [ ] Related documentation is updated.

Use `npm run lint`, `npm run build`, and `npm test` for repository-wide checks as appropriate. The test command's rendered-page check requires the site to be running at `http://localhost:3000/`.
